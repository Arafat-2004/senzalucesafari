# 🔐 Admin Security & User Access Manual
### Senza Luce Safaris — Operations & System Administration Guide

This manual serves as the official reference for managing administrator accounts, roles, access levels, passwords, and security controls for the Senza Luce Safaris platform.

---

## 1. Accessing the Control Center

- **Admin Login Portal**: `https://www.senzalucesafari.com/admin/login`
- **Dashboard Access**: Unauthorized logins or expired sessions are intercepted by the security middleware and redirected back to the login screen with the message `?reason=session_expired`.
- **Allowed Domains**: Controlled in **Admin Settings > Environment**. Only requests originating from verified production domains or localhost can access backend administrative resources.

---

## 2. Role-Based Access Control (RBAC) Matrix

The platform implements a strict Permission-Based access system. Each administrator is assigned one of four standard roles. The permissions associated with each role are mapped below:

| Feature Area / Module | Super Admin | Manager | Editor | Support Agent |
| :--- | :---: | :---: | :---: | :---: |
| **System Settings** | Read / Write | Read Only | Blocked | Blocked |
| **SMTP / Webhooks** | Read / Write | Blocked | Blocked | Blocked |
| **Role & Perms Config** | Read / Write | Blocked | Blocked | Blocked |
| **Bookings Management**| Read / Write | Read / Write | Read / Write | Read Only |
| **Safari & Tour Packages**| Read / Write | Read / Write | Read / Write | Read Only |
| **Destinations / CMS** | Read / Write | Read / Write | Read / Write | Read Only |
| **Customer Enquiries** | Read / Write | Read / Write | Read / Write | Read / Write |
| **Reviews Moderation** | Read / Write | Read / Write | Read / Write | Blocked |
| **Audit Log Viewing** | Read / Write | Read Only | Blocked | Blocked |

> [!TIP]
> Permissions can be customized dynamically by a Super Admin in the **Roles & Permissions** tab under `/admin/settings`.

## 3. Account & Password Policies

To protect customer information and booking schedules, all administrative accounts must adhere to the following standards:

### A. Password Requirements
- Minimum of **12 characters**.
- Must contain at least one uppercase letter, one lowercase letter, one number, and one special character (e.g., `@`, `#`, `$`, `&`).
- Password hashes are computed using **Bcrypt** with a secure work factor (10–12 salt rounds). Plaintext passwords are never stored in the database.

### B. Brute-Force Protection
- Login endpoints are rate-limited via **Upstash Redis**.
- If an account attempts to log in with incorrect credentials more than **5 times within 1 minute**, further attempts from that IP address are temporarily blocked.

## 4. Multi-Factor Authentication (MFA / 2FA)

Multi-Factor Authentication adds an extra layer of protection by requiring a 6-digit verification code from a mobile device to log in.

### A. Setup Process for Administrators
1. Log in to the Admin Panel.
2. Navigate to **Security & Sessions** or `/admin/mfa`.
3. Open a TOTP-compatible authenticator app (such as Google Authenticator, Microsoft Authenticator, or Bitwarden) on your mobile device.
4. Scan the QR code displayed on screen.
5. Input the 6-digit code generated by the app to verify integration.
6. Copy the **Emergency Recovery Codes** and store them in a secure password manager.

### B. MFA Enforcement
Super Admins can globally toggle the **Force MFA** setting in **Admin Settings > Security**. If enabled, all administrative accounts will be locked out of the dashboard until they complete their MFA registration flow.

### C. MFA Emergency Recovery Procedures
If an administrator loses access to their authenticator device, their MFA check can be disabled using one of two methods:

#### Method 1: Recovery Codes
During the MFA setup flow, the user is given five 8-character recovery codes. Entering any valid unused recovery code in place of the 6-digit OTP code bypasses the MFA lock and logs the user in.

#### Method 2: Database Override (For Developers)
If no recovery codes are available, a Super Admin or developer with direct database access can disable MFA for a specific user.
Execute the following SQL query directly in the Supabase SQL editor:
```sql
UPDATE "AdminUser" 
SET "mfaEnabled" = false, "mfaSecret" = null 
WHERE "email" = 'user@senzalucesafari.com';
```
Alternatively, run the built-in CLI helper script:
```bash
# Deactivates MFA for a specific account via command line
npx tsx scripts/disable-mfa.ts user@senzalucesafari.com
```

## 5. Security & Session Maintenance

- **Session Expiration**: Admin sessions automatically expire after **2 hours of inactivity**. This duration can be configured in the global Settings panel.
- **Audit Trails**: Every administrative action (modifying tours, deleting reviews, editing settings, changing user roles) is recorded in the `AuditLogs` table. The audit log lists:
  - The email of the administrator who made the change.
  - The IP address and browser client used.
  - The resource changed and the timestamp of the transaction.
- **Reviewing Logs**: Logs can be audited directly at `/admin/audit-logs`.
